# Library & Reading Tracker

Кроссплатформенное мобильное приложение на **Flutter / Dart** для учёта прочитанных книг, статусов чтения и статистики.
Индивидуальный проект, **тема № 15** — «Library & Reading Tracker».

> Статус проекта: **недели 1–8 выполнены** (см. [чек-лист](#прогресс-по-неделям)). Инструкция по запуску — в [SETUP.md](SETUP.md).

---

## 1. Постановка задачи

### Цель
Дать читателю одно место, где можно вести личную библиотеку: находить книги в открытом каталоге, отмечать, что он хочет прочитать / читает / уже прочитал, фиксировать прогресс, оценки и заметки, а также видеть статистику чтения и прогресс по годовой цели. Данные должны быть доступны без интернета и синхронизироваться между устройствами.

### Целевая аудитория
- студенты и школьники, читающие по программе и для себя;
- активные читатели, которые хотят отслеживать цель «N книг в год»;
- люди, которые пользуются несколькими устройствами и не хотят терять заметки.

### Аналоги

| Приложение | Что делает хорошо | Чего не хватает (наше преимущество) |
| --- | --- | --- |
| **Goodreads** | Огромный каталог, соцсеть, годовой челлендж | Перегруженный интерфейс, реклама, слабая работа офлайн |
| **The StoryGraph** | Подробная статистика, рекомендации | Основной упор на веб, платные функции |
| **Basmo / Bookshelf** | Простой трекер, заметки, прогресс | Нет единого каталога поиска и облачной синхронизации в бесплатной версии |

Наше решение: лёгкий интерфейс на Material 3, поиск в Open Library, offline-first и бесплатная синхронизация через Firebase.

### Список экранов
1. Вход / регистрация (email, Google)
2. Библиотека (список / сетка, фильтры по статусу)
3. Карточка книги (статус, прогресс, оценка, заметка)
4. Добавление / редактирование книги
5. Поиск по каталогу Open Library
6. Статистика (цель на год, числа, график по месяцам)
7. Настройки (тема, язык, цель, push, аккаунт)

### MVP (функции, которые реализуем)
- учёт книг: добавление вручную и из каталога, редактирование, удаление;
- статусы «хочу прочитать / читаю / прочитано», прогресс по страницам, оценка 1–5, заметка;
- поиск по Open Library (debounce, pull-to-refresh, состояния loading / error / empty);
- статистика: итоги, средняя оценка, график по месяцам, годовая цель;
- офлайн-режим (Hive) и синхронизация с Firestore;
- вход по email и Google, push-уведомления (FCM);
- светлая / тёмная тема, русский и английский языки.

В дальнейших неделях: карта библиотек/книжных рядом (неделя 9), пагинация и профилирование (10), **сканер ISBN** через камеру и Platform Channel (11), CI/CD (12), тесты (13), публикация (14).

## 2. Стек и архитектура

| Задача | Решение |
| --- | --- |
| Язык | Dart 3 с null safety |
| UI | Flutter, Material 3, светлая/тёмная тема, адаптивная вёрстка |
| Состояние | Provider (настройки) + BLoC (основная логика) |
| DI | get_it |
| Навигация | go_router (`StatefulShellRoute`, `redirect`, именованные маршруты) |
| Сеть / JSON | dio + json_serializable |
| Локально | SharedPreferences (настройки), Hive (книги, кэш поиска) |
| Backend | Firebase Auth, Cloud Firestore, Cloud Messaging |

### Слои (Clean Architecture, упрощённо)

```
lib/
├─ core/                 # DI (get_it), роутер, тема, локализация, Dio
├─ domain/               # чистый Dart: сущности и интерфейсы репозиториев
│   ├─ entities/         # Book, ReadingStatus, ReadingStats, SearchResult, AuthUser
│   └─ repositories/     # LibraryRepository, SearchRepository, AuthRepository
├─ data/                 # реализации и источники данных
│   ├─ models/           # DTO + json_serializable
│   ├─ datasources/      # OpenLibraryApi, Hive, Firestore
│   ├─ repositories/     # *Impl (паттерн Repository)
│   └─ services/         # PushService (FCM)
└─ presentation/         # UI и управление состоянием
    ├─ auth/ library/ search/ stats/ settings/ shell/ common/
```

Зависимости направлены внутрь: `presentation → domain ← data`. Domain ничего не знает о Flutter, Firebase и Dio, поэтому его логику (`Book.changeStatus`, `ReadingStats`) легко тестировать обычными unit-тестами.

Поток данных:
`Widget → событие → BLoC → Repository (интерфейс) → Impl → Hive / Firestore / API → состояние → Widget`

## 3. Управление состоянием: сравнение подходов (неделя 3)

Одна и та же функция «избранное» реализована тремя способами — см. `examples/week3_state/`.

| Подход | Плюсы | Минусы | Когда применять |
| --- | --- | --- | --- |
| **setState** | Ничего устанавливать, максимально просто | Состояние привязано к одному виджету; для общего состояния приходится «поднимать» его вверх и передавать через конструкторы | Локальное состояние одного виджета: переключатель, анимация, поле формы |
| **InheritedWidget** | Встроен во Flutter; состояние доступно любому потомку | Много шаблонного кода (host + scope + `of` + `updateShouldNotify`), нет удобных инструментов | Для понимания механизма; практически — как основа для библиотек |
| **Provider** | Мало кода, `watch` / `read` / `select`, точечные перерисовки, `ChangeNotifier` | Логика в `ChangeNotifier` легко смешивается с UI; нет строгой структуры событий | Простое общее состояние: настройки, тема, небольшие модели |
| **BLoC** | События и состояния явны, предсказуемость, отличная тестируемость (`bloc_test`), `transformer` для debounce / droppable | Больше кода, выше порог входа | Сложная бизнес-логика: загрузка, поиск, синхронизация, авторизация |

### Что выбрано в проекте и почему
- **Provider** (`SettingsController`) — тема, язык и годовая цель: это простое глобальное состояние, для которого события и состояния были бы избыточны.
- **BLoC** — `LibraryBloc`, `SearchBloc`, `AuthBloc`: в них асинхронные операции, несколько состояний (loading / success / error / empty) и необходимость управлять конкурентностью. Например, в `SearchBloc` `restartable()` вместе с задержкой даёт debounce, а `droppable()` защищает от повторных refresh. Кроме того, BLoC хорошо ложится на слой presentation и легко покрывается тестами.
- Riverpod не использовался: BLoC даёт нужную строгость, а DI решает `get_it`.

## 4. REST API и офлайн-стратегия (недели 5–6)

**Источник данных:** [Open Library Search API](https://openlibrary.org/dev/docs/api/search) — публичный, без ключа.
Запрос: `GET https://openlibrary.org/search.json?q=...&fields=key,title,author_name,first_publish_year,cover_i,number_of_pages_median,isbn`.
Обложки: `https://covers.openlibrary.org/b/id/{cover_i}-M.jpg`.

- `dio` с таймаутами (connect 10 c, receive 15 c), `DioException` преобразуется в доменный `Failure` (network / timeout / server / parse).
- Модели: `BookDocDto`, `SearchResponseDto` (`json_serializable`) → `Book`.
- UI-состояния: loading / success / empty / error (+ повтор), поиск с debounce 400 мс, pull-to-refresh.

**Offline-first:**
- **Библиотека**: источник истины для UI — Hive (отдельный box на пользователя `books_<uid>`). Любая запись сначала пишется локально, потом отправляется в Firestore (очередь Firestore отправит её при появлении сети).
- **Поиск**: успешные ответы кэшируются в Hive; при отсутствии сети показываются сохранённые результаты по тому же запросу с баннером «Нет сети».
- **Настройки**: SharedPreferences (`theme_mode`, `language`, `yearly_goal`).

## 5. Firebase (неделя 8)

- **Authentication**: email + пароль и Google. Сессия сохраняется между запусками.
- **Защита маршрутов**: `GoRouter.redirect` — без входа доступны только `/login` и `/register`; `GoRouterRefreshStream` пересчитывает редирект при смене состояния `AuthBloc`.
- **Cloud Firestore**
  ```
  users/{uid}                    # профиль: fcmTokens[], tokenUpdatedAt
  users/{uid}/books/{bookId}     # книга (JSON-представление Book)
  ```
  Синхронизация: при входе и по pull-to-refresh сравниваются `updatedAt` (last-write-wins), недостающие записи отправляются в облако.
- **Security Rules** (`firestore.rules`): доступ только владельцу (`request.auth.uid == uid`), валидация названия, статуса, рейтинга и заметки, всё остальное запрещено.
- **Cloud Messaging**: запрос разрешения, получение токена, сохранение токена в `users/{uid}`, показ уведомлений в открытом приложении (SnackBar), фоновый обработчик. Токен виден в «Настройках» — его можно вставить в Firebase Console → Messaging → «Отправить тестовое сообщение».

## 7. Известные ограничения
- Удаление книги не синхронизируется как «надгробие»: если удалить книгу офлайн на одном устройстве, при синхронизации со вторым она может вернуться.
- Поиск пока загружает только первую страницу (20 результатов); пагинация — неделя 10.
- Сканер ISBN появится в неделе 11.
